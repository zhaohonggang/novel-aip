# 04 双阶段实体抽取与结构化分析

## 4.1 设计动机：不对称计算分配

| 阶段 | 计算特征 | 硬件 | 处理比例 | 产出 |
|------|----------|------|----------|------|
| **Stage 1: CPU NER** | 规则/统计、高吞吐、低延迟 | CPU (全核) | 100% 文档 | Top-5 人名/地名频次 |
| **Stage 2: LLM 结构化** | 推理密集、高显存、高延迟 | GPU (ROCm) | < 1% 文档 (高密度片段) | `NovelSchema` JSON |

**核心洞察**：全文直接喂 LLM 成本高、上下文窗口不足、幻觉率高。仅对「高密度信息片段」调用 LLM，可将推理成本降低 99%+。

## 4.2 Stage 1: 快速 CPU-NER (spaCy)

### 管道裁剪策略
```python
nlp = spacy.load("zh_core_web_sm", disable=["parser", "tagger", "senter"])
# 保留: tok2vec + ner + attribute_ruler
# 移除: parser(依存句法)、tagger(词性)、senter(句边界)
```
| 组件 | 是否保留 | 理由 |
|------|----------|------|
| `tok2vec` | ✅ | 嵌入层，NER 依赖 |
| `ner` | ✅ | 核心实体识别 |
| `attribute_ruler` | ✅ | 实体规范化规则 |
| `parser` | ❌ | 依存句法，NER 不依赖 |
| `tagger` | ❌ | 词性标注，NER 不依赖 |
| `senter` | ❌ | 句边界检测，NER 不依赖 |

### 实体抽取与频次统计
```python
def extract_top_entities(text, nlp, head_chars=50_000, top_n=5):
    person_ctr = Counter()
    gpe_ctr = Counter()
    doc = nlp(text[:head_chars])
    for ent in doc.ents:
        if ent.label_ == "PERSON":
            person_ctr[ent.text.strip()] += 1
        elif ent.label_ == "GPE":
            gpe_ctr[ent.text.strip()] += 1
    return person_ctr.most_common(top_n), gpe_ctr.most_common(top_n)
```
- **切片长度**：50,000 字符 ≈ 2.5 万中文字 ≈ 前 3-5 章
- **实体类型**：`PERSON` (人物)、`GPE` (地理政治实体：城市/国家/门派/星球)
- **输出**：Top-5 高频人物名、Top-5 高频地点名

### spaCy 中文模型能力边界
| 实体类型 | 覆盖示例 | 局限 |
|----------|----------|------|
| `PERSON` | "严平"、"林美美"、"吴仲军" | 仅识别显性人名，代词/别名需 LLM 兜底 |
| `GPE` | "广东"、"长沙"、"墨镜人"(误识) | 门派/星球/虚构地名常漏识，需 LLM 补全 |
| `ORG` | 未启用 | 可扩展启用 `ORG` 捕捉帮派/宗门/公司 |

## 4.3 Stage 2: 高密度上下文组装

### 4.3.1 引言切片
```python
INTRO_CHARS = 2_000  # 约 1,000 中文字，覆盖开篇设定
intro = text[:INTRO_CHARS]
```
- 2,000 字符 ≈ 小说开篇「钩子」段落，包含核心设定、主角登场、世界观钩子

### 4.3.2 章节概览抽取
```python
CHAPTER_HEADER_RE = re.compile(
    r"第[一二三四五六七八九十百千万〇零0-9]+[章节回卷集部篇段]"
)

def build_dense_snippet(text, intro_chars=2_000, max_headers=40):
    intro = text[:intro_chars].strip()
    chapter_lines = [
        line.strip() for line in text[:200_000].splitlines()
        if CHAPTER_HEADER_RE.search(line)
    ]
    # 去重 + 截断
    headers = []
    seen = set()
    for line in chapter_lines:
        if line not in seen:
            seen.add(line)
            headers.append(line[:80])
            if len(headers) >= max_headers:
                break
    parts = [intro]
    if headers:
        parts.append("章节概览: " + " / ".join(headers))
    return "\n\n".join(parts)
```
- **正则覆盖**：支持中文数字(一/二/三)、阿拉伯数字、章/节/回/卷/集/部/篇/段
- **扫描范围**：前 200k 字符 ≈ 前 10 万字 ≈ 完整目录区
- **去重**：避免重复章节名(如「第一章 xxx」出现多次)
- **输出格式**：`引言\n\n章节概览: 第1章 xxx / 第2章 yyy / ...`

### 4.3.3 稠密片段示例
```
【引言前 2000 字】
...主角严平在雷雨夜回到故乡小镇，祖宅传出异响...

章节概览: 第1章 雷雨夜 / 第2章 祖宅异响 / 第3章 道士作法 / 第5章 灵异初现 / 第10章 真相大白 / ...
```

## 4.4 LLM 结构化抽取

### 4.4.1 Schema 定义 (`NovelSchema`)
```python
class NovelSchema(BaseModel):
    main_genres: list[str] = Field(
        default_factory=list,
        max_length=3,
        description="最多 3 个主流体裁标签"
    )
    story_tropes: list[str] = Field(
        default_factory=list,
        description="情节套路/梗，如：系统流、背叛、复仇、穿越、重生"
    )
    one_sentence_summary: str = Field(
        default="",
        max_length=200,
        description="单句核心梗概，≤200 字"
    )
```

### 4.4.2 ChatOpenAI 本地化配置
```python
llm = ChatOpenAI(
    base_url="http://127.0.0.1:8080/v1",
    model="qwen2.5-27b-instruct",
    api_key="not-needed-local-inference",  # 任意字符串
    temperature=0.1,        # 低温度 → 确定性收敛
    max_retries=2,
    request_timeout=300,    # 27B 推理耗时长
)
```
| 参数 | 值 | 理由 |
|------|-----|------|
| `temperature` | 0.1 | 强制确定性 JSON 输出，抑制幻觉 |
| `max_retries` | 2 | 网络抖动自愈 |
| `request_timeout` | 300s | 27B 模型单次推理可达 2-3 分钟 |

### 4.4.3 Prompt 模板工程
```python
system_content = f"""
你是一个经验丰富的中文网络小说编辑。
任务：根据小说开头片段与章节概览，抽取结构化元数据。
约束：
- main_genres ≤ 3 个体裁标签 (如: 玄幻/都市/悬疑)
- story_tropes 给出情节套路 (如: 系统流/背叛/复仇)
- one_sentence_summary ≤ 200 字，单句概括核心设定
必须只输出符合 JSON Schema 的对象，不输出任何其他文字。

{escaped_format_instructions}
"""

prompt = ChatPromptTemplate.from_messages([
    ("system", system_content),
    ("human", "小说片段与章节概览：\n\n{input}\n\n请输出 JSON。")
])
chain = prompt | llm | JsonOutputParser(pydantic_object=NovelSchema)
```
**关键技巧**：`format_instructions` 包含 `{` `}` 必须双花括号转义 `{{` `}}`，否则被 `ChatPromptTemplate` 误认为模板变量导致 `INVALID_PROMPT_INPUT`。

## 4.5 降级策略 (LLM 不可用时)

```python
def fallback_schema(main_characters, key_locations):
    genre_hints = {
        "玄幻": ("先天", "修炼", "丹田", "灵根", "境界", "法宝", "仙"),
        "都市": ("公司", "集团", "都市", "上班", "总裁", "商场"),
        "历史": ("皇帝", "朝廷", "将军", "天下", "王朝", "兵马"),
        "悬疑": ("警方", "案件", "侦探", "密室", "凶手", "线索"),
        "科幻": ("宇宙", "外星", "飞船", "科技", "量子", "机甲"),
        "言情": ("眼泪", "婚礼", "结婚", "离婚", "误会", "心动"),
    }
    text_sample = "".join(main_characters + key_locations)
    matched = [g for g, hints in genre_hints.items() if any(h in text_sample for h in hints)]
    return NovelSchema(
        main_genres=matched[:3],
        story_tropes=[],
        one_sentence_summary=f"以{('、'.join(main_characters) or '主角')}为中心展开的未知类型故事。"
    )
```
- **关键词启发式**：基于实体名/地名中的领域词匹配体裁
- **保底输出**：保证 Schema 结构完整，避免下游解析崩溃
- **触发条件**：LLM 抛异常、超时、返回空 summary、JSON 解析失败

### 元信息解析
```python
def parse_meta(path: Path):
    folder = path.parent.name
    # 目录名示例: "【纹面】（完结） 作者：漂泊旅人[原创]"
    title = re.search(r"【([^】]+)】", folder)?.group(1)
    author = re.search(r"作者[:：]([^\]\[]+?)(?:\[|$)", folder)?.group(1)
    return title, author
```

## 4.8 性能与成本分析

| 指标 | 数值 | 备注 |
|------|------|------|
| Stage 1 NER 耗时 | ~0.3 s/文档 | spaCy CPU 单核 |
| Stage 2 LLM 耗时 | 90-180 s/文档 | Qwen-27B Q6_K @ ROCm |
| 显存占用 | ~16 GB | Q6_K 量化 + 上下文 8k |
| 批量吞吐 | ~2-4 文档/分钟 | 受限于 LLM 串行推理 |
| 降级模式耗时 | < 0.5 s/文档 | 纯 CPU 启发式 |

### 优化建议
| 方向 | 预期收益 | 实现复杂度 |
|------|----------|------------|
| 批量 Prompt (10 文档/次) | 5-8x 吞吐提升 | 中 (需重构 Prompt 支持数组) |
| vLLM / TGI 替代 llama.cpp | 3-5x 吞吐 | 高 (需 CUDA/ROCm 重新编译) |
| 量化 Q4_K_M (更小) | 显存 -30%，速度 +20% | 低 (仅换模型文件) |
| 缓存重复片段 | 视重复率而定 | 低 (LRU 缓存) |
