# 05 向量数据库设计与数据入库

## 5.1 Schema 设计 (`schema.sql`)

### 5.1.1 表结构 `novel_catalog`
```sql
CREATE TABLE novel_catalog (
    id                   SERIAL PRIMARY KEY,
    title                VARCHAR(512) NOT NULL,
    author               VARCHAR(256),
    main_characters      TEXT[],
    key_locations        TEXT[],
    genres               TEXT[],
    tropes               TEXT[],
    one_liner_summary    TEXT,
    summary_embedding    VECTOR(768),
    raw_json_payload     JSONB,
    processed_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

| 列 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | `SERIAL` | PK | 自增主键 |
| `title` | `VARCHAR(512)` | NOT NULL | 书名 |
| `author` | `VARCHAR(256)` | | 作者 |
| `main_characters` | `TEXT[]` | | Stage 1 Top-5 人物 |
| `key_locations` | `TEXT[]` | | Stage 1 Top-5 地点 |
| `genres` | `TEXT[]` | | LLM 抽取体裁 (≤3) |
| `tropes` | `TEXT[]` | | LLM 抽取套路 |
| `one_liner_summary` | `TEXT` | | 一句话梗概 (≤200 字) |
| `summary_embedding` | `VECTOR(768)` | | nomic-embed-text-v1.5 稠密向量 |
| `raw_json_payload` | `JSONB` | | 全量原始记录 (含 source_file 等) |
| `processed_at` | `TIMESTAMP` | DEFAULT NOW | 入库时间戳 |

### 5.1.2 索引策略

```sql
-- GIN 倒排索引：数组精确包含查询
CREATE INDEX idx_novel_genres_gin           ON novel_catalog USING GIN (genres);
CREATE INDEX idx_novel_tropes_gin           ON novel_catalog USING GIN (tropes);
CREATE INDEX idx_novel_main_characters_gin  ON novel_catalog USING GIN (main_characters);
CREATE INDEX idx_novel_key_locations_gin    ON novel_catalog USING GIN (key_locations);

-- HNSW 近似最近邻：稠密向量余弦相似度
CREATE INDEX idx_novel_hnsw
    ON novel_catalog USING hnsw (summary_embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);
```

| 索引 | 类型 | 适用查询 | 存储开销 |
|------|------|----------|----------|
| `genres` | GIN | `genres @> ARRAY['玄幻']` | ~1.2x 列大小 |
| `tropes` | GIN | `tropes @> ARRAY['复仇']` | ~1.2x |
| `main_characters` | GIN | `main_characters @> ARRAY['严平']` | ~1.2x |
| `key_locations` | GIN | `key_locations @> ARRAY['广东']` | ~1.2x |
| `summary_embedding` | HNSW | `embedding <=> query_vec` | ~1.5x 向量大小 |

### HNSW 参数调优指南
| 参数 | 默认 | 推荐范围 | 影响 |
|------|------|----------|------|
| `m` | 16 | 8-32 | 图连接度，越大召回越高、构建越慢、内存越大 |
| `ef_construction` | 64 | 40-200 | 构建时搜索深度，越大质量越高、构建越慢 |
| `ef_search` | 40 (运行时) | 40-400 | 查询时搜索深度，运行时 `SET hnsw.ef_search = 100;` |

> **经验法则**：百万级数据 `m=16, ef_construction=64` 平衡最优；十万级可降至 `m=8, ef_construction=40`。

## 5.2 数据入库流水线 (`database_worker.py`)

### 5.2.1 核心流程
```mermaid
flowchart LR
    A[records.json] --> B[加载记录]
    B --> C[提取 one_liner_summary]
    C --> D[nomic-embed-text-v1.5 批量嵌入]
    D --> E[格式化向量字符串]
    E --> F[execute_values 批量插入]
    F --> G[事务提交]
    G --> H[重试/熔断]
```

### 5.2.2 嵌入模型配置
```python
EMBEDDING_MODEL = "nomic-ai/nomic-embed-text-v1.5"
EMBEDDING_DIM = 768
BATCH_SIZE = 100

# 任务前缀 (官方推荐)
TASK_PREFIX_RETRIEVAL = "search_document: "
TASK_PREFIX_QUERY = "search_query: "

def embed_summaries(embedder, summaries, batch_size=BATCH_SIZE):
    texts = [TASK_PREFIX_RETRIEVAL + s if s else s for s in summaries]
    vectors = embedder.encode(texts, batch_size=batch_size, convert_to_numpy=True)
    return [list(map(float, row)) for row in vectors]
```
- **任务前缀关键**：nomic 系列模型需区分「文档侧」与「查询侧」前缀，否则语义空间错位
- **维度固定 768**：`nomic-embed-text-v1.5` 原生 768 维，Matryoshka 截断不改变维度

### 5.2.3 向量字符串格式化
```python
def format_vector(vector: Sequence[float]) -> str:
    # pgvector 接受 "[0.1,0.2,...]" 文本字面量显式转型
    return "[" + ",".join(f"{v:.8f}" for v in vector) + "]"
```
- 精度 8 位小数 ≈ 1e-8，足够余弦相似度精度
- `NaN/Inf` 防护已在 `app.py` 中处理

### 5.2.4 批量事务插入 (`execute_values`)
```python
def insert_chunk(records, embeddings, conn_info, batch_size=100):
    conn = psycopg2.connect(**conn_info)
    try:
        with conn.cursor() as cur:
            insert_query = sql.SQL(
                "INSERT INTO novel_catalog ({cols}) VALUES %s"
            ).format(cols=sql.SQL(", ").join(map(sql.Identifier, COLS)))
            
            row_template = "(%s, %s, %s, %s, %s, %s, %s, %s::vector, %s)"
            rows = []
            for rec, vec in zip(records, embeddings):
                rows.append((
                    rec["title"], rec.get("author"),
                    rec.get("main_characters"), rec.get("key_locations"),
                    rec.get("genres"), rec.get("tropes"),
                    rec.get("one_liner_summary"),
                    format_vector(vec),
                    json.dumps(rec.get("raw_json_payload") or {}, ensure_ascii=False),
                ))
            extras.execute_values(
                cur, insert_query, rows,
                template=row_template, page_size=batch_size
            )
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()
```
- `execute_values` 单条 SQL 批量插入，避免 N 次 round-trip
- `template` 显式 `%s::vector` 显式转型，避免隐式转换失败
- `page_size=100` 与 `BATCH_SIZE` 对齐，内存常数级

### 5.2.4 重试与熔断机制
```python
RETRY_LIMIT = 3
RETRY_DELAY_SECONDS = 5

def process_records(records, embedder, conn_info, ...):
    for chunk in chunks(records, BATCH_SIZE):
        attempt = 0
        while True:
            try:
                inserted = insert_chunk(chunk, ...)
                break
            except psycopg2.OperationalError as e:
                attempt += 1
                if attempt >= RETRY_LIMIT:
                    return False  # 崩溃标志
                time.sleep(RETRY_DELAY_SECONDS)
            except Exception:
                return False  # 非连接错误直接失败
    return True
```
| 错误类型 | 处理策略 |
|----------|----------|
| `OperationalError` (连接断开/超时) | 指数退避重试 3 次，间隔 5s |
| `IntegrityError` (PK 冲突) | 回滚，记录错误，继续下一批 |
| `DataError` (向量维度不匹配) | 回滚，记录错误，继续下一批 |
| 其他异常 | 立即失败，置崩溃标志 |

## 5.3 运行接口

```bash
python database_worker.py --payload records.json [选项]

选项:
  --payload PATH     JSON 文件路径 (必填)，数组或 {records: [...]}
  --model STR        嵌入模型名 (默认 nomic-ai/nomic-embed-text-v1.5)
  --batch-size INT   批量大小 (默认 100)
  --log-level LEVEL  日志级别 (默认 INFO)
```

## 5.5 性能基准

| 数据量 | 嵌入耗时 | 写入耗时 | 总耗时 | 吞吐 |
|--------|----------|----------|--------|------|
| 6 条 (样本) | ~1.2 s | ~0.4 s | ~1.6 s | ~3.7 rec/s |
| 1,000 条 (估算) | ~200 s | ~30 s | ~230 s | ~4.3 rec/s |
| 10,000 条 (估算) | ~2,000 s | ~300 s | ~2,300 s | ~4.3 rec/s |

> 瓶颈在嵌入模型推理，CPU 推理约 1.5 it/s (batch=100)；GPU 推理可提升 10-20x。

### 扩展建议
| 方向 | 预期提升 | 实现 |
|------|----------|------|
| GPU 加速 (CUDA/ROCm) | 10-20x | `device="cuda"` 或 `device="hip"` |
| 多进程并行嵌入 | N 倍 (N=CPU 核心) | `multiprocessing.Pool` + 模型共享内存 |
| 批量大小调大 (512) | 吞吐 +20% | 显存允许前提下 |
| 连接池 (`psycopg2.pool`) | 减少连接开销 | `ThreadedConnectionPool` |

## 5.6 数据库维护操作

### 索引重建 (在线)
```sql
-- GIN 索引并发重建 (不阻塞写入)
REINDEX INDEX CONCURRENTLY idx_novel_tropes_gin;

-- HNSW 索引无 CONCURRENTLY 支持，需低峰期
REINDEX INDEX idx_novel_hnsw;
```

### HNSW 搜索精度调优 (运行时)
```sql
-- 提高召回率 (查询时生效)
SET hnsw.ef_search = 200;
SELECT ... FROM novel_catalog ORDER BY summary_embedding <=> $1 LIMIT 10;
```

### 统计信息更新
```sql
ANALYZE novel_catalog;
-- 或自动: autovacuum 配置
```

### 备份与恢复
```bash
# 逻辑备份 (含向量)
pg_dump -U postgres -d fileindex -Fc -f backup.dump

# 恢复
pg_restore -U postgres -d fileindex -c backup.dump
```
